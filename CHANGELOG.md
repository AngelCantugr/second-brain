# Changelog

## Unreleased

- Stop incremental sync from losing graph edges between notes that did not change (`docs/bug-hunt-2026-11-10.md`, items 16 and 17). Updating a note deleted every edge of the notes affected by it, then rebuilt only the edges those notes proposed themselves, so an edge that existed because another note listed one of them as a nearest note was dropped until the next full sync. Deleting a note, or moving it semantically away, also left its former neighbours one neighbour short instead of taking the next nearest note. The update now reads every note's nearest notes from the similarity matrix it already builds, rebuilds each affected note's edges from both sides, and works out from the previous centroids which notes had a changed or deleted note among their nearest, so they are rescored too. Across 3,000 random edits and deletes, with default and non-default weights, the stored edges matched a rescore of the whole vault every time; before the fix the same comparison failed on every seed tried. Semantic scores still use the mean stored by the last full sync. Run `second-brain sync --mode full` once to restore edges already lost.
- Fix two parsing mistakes from the bug hunt (`docs/bug-hunt-2026-11-10.md`, items 10 and 11). A `#` inside a wikilink (`[[#Summary]]`, `[[Note#Heading]]`) or a character reference (`&#x27;`) is no longer read as a tag. A wikilink alias written with an escaped pipe, as Obsidian requires inside a table cell (`[[Target\|shown]]`), now yields the target `Target` instead of `Target\`, so it resolves in the graph and no longer shows up as a ghost in `rag.map`. A bare `#fff` in prose is still a tag, as in Obsidian. Run `second-brain sync --mode full` once to re-extract tags and links for notes that are already indexed.
- Start the vault watcher from the MCP server. `watch_enabled = true` was the default but nothing ever started the watcher, while `rag.status` reported `watcher_state: "enabled"` (`docs/bug-hunt-2026-11-10.md`, items 1 and 4). `second-brain-mcp` now watches the vault on a background thread and indexes notes as they change; the CLI does not. Changes are collected until the vault has been quiet for the new `watch_debounce_seconds` (default 5), then each note is synced once, so an autosaving editor does not re-embed a note on every save, and a change no longer waits for the next filesystem event before it is synced. A deleted note is removed with a single-file sync instead of a full incremental scan; moving, renaming or deleting a folder runs one incremental sync. A failed sync is logged to stderr and no longer ends the watch loop. Paths under the index stores are ignored, so a default config with `data/` inside the vault does not trigger itself. Sync and vector search take turns on a lock, so a search can wait for a note sync in progress. `rag.status` gains `watcher_running`. Only the vault is watched; code sources still need a sync. **Upgrade note:** an MCP server whose config has `watch_enabled = true`, including by default, starts embedding changed notes in the background after this change; set it to `false` to keep indexing manual.
- Fix three sync and search failures found in a bug hunt (`docs/bug-hunt-2026-11-10.md`). `sync --mode file` raised `ValueError` for every file when `vault_path` was reached through a symlink or a relative `..` path; it now resolves the vault root the same way it resolves the file. `sync --mode file` on a note deleted from disk raised and left the note indexed; it now removes the note from both indexes, the graph and sync state, and still raises `FileNotFoundError` for a path that was never indexed. Searching before the first sync, or over a vault of empty notes, raised `Collection ... not found`; it now returns no hits. A missing vault root (an unmounted drive) no longer looks like an empty vault: full and incremental sync report `vault: path not found; its index entries are kept` in `errors` and delete nothing, file-mode sync raises, and `rag.status` does not count those notes as missing. A mount point left behind as an empty folder is not detected.
- Add doc roles and cut drift noise found on a real vault with one repo indexed, where none of the 1,215 flagged pairs was a real disagreement. Every note and repo doc now has a role from its path: `reference` (living docs: READMEs, `SKILL.md`, and anything unmatched), `record` (designs, plans, specs, ADRs, and file or folder names holding a date) or `history` (changelogs). A `doc_roles` table, top level for the vault and per `[[code_sources]]` table, replaces the default globs of each role it names; roles are computed from the config when asked, so no re-sync is needed. `rag.drift` takes `roles` (default `["reference"]`), lists only those docs' pairs, and adds `records`: one row per record whose code moved, with `tracked`, `changed`, `gone`, `moved_share`, `gone_mentions` and `changed_at`, most moved first. Records were 99% of the flagged pairs in that repo, and listing them pair by pair buried the living docs that actually named deleted skills. Changelog mentions are no longer tracked. Pairs carry `evidence.role`. `rag.search` and `rag.query` accept `filters.doc_role`. A mention that matched a file now keeps matching it while that file still matches, instead of dangling (`unresolved`) when another file starts defining the same name. In vault notes, a one-word bare name (`Task`, `base.py`, `util.go:12`) links only if the note also names that repo another way (its name, a URL, a path with a folder, or a multi-word name), so a Go note's `Task` struct or a design note's own `base.py` no longer links to a same-named file in a code source; such mentions drop their drift row instead of dangling. Repo docs resolve one-word names in their own repo as before.
- Add drift detection between notes and the code they mention, and a `rag.drift` MCP tool. Each sync now records, for every mention that resolves to a code-source file or symbol, the code fingerprint the note was last written against: a hash of the symbol's whole declaration (body included, ignoring indentation and position) for a symbol mention, the file's content hash otherwise. A pair is `stale` when that code changed and the note has not changed since, and `dangling` when a mention that used to resolve no longer does (`file_removed`, `symbol_removed`, or `unresolved` when the name became ambiguous), with candidates for where it went. Editing a note re-acknowledges all of its mentions; a full sync does not. `rag.drift` returns the pairs with the note excerpts that contain the mention, the symbol's outline, line span and local path, and change dates, so the calling agent judges whether they disagree; the server judges nothing. Filters: `status`, `note_path`, `repo`, `levels` (`symbol`, `file`, `repo`; repo mentions, which resolve to a README that changes in nearly every pull request, are left out by default), `limit`; symbol pairs are listed first. The first sync records a baseline (nothing stale). `fts.sqlite` gains a `code_mentions` table and `note_meta.code_json` gains `hash`, `mtime` and `symbol_hashes`, added automatically; run `second-brain sync --mode full` once so existing notes and code files record them. Matching notes to code by embedding similarity alone was measured and not added: see `docs/drift-detection.md`.
- Add `code_source_weight` (above 0, at most 1; default 1.0) to rank code sources below vault notes for questions about the vault. A repo can hold as many chunks as the vault and shares its vocabulary, so its chunks took top ranks from notes. For a query that names nothing distinctive in a code source, the fused score of every code-source hit is multiplied by the weight; a query that names the repo, a directory or file name, or a symbol keeps its ranking. Names in more than 2 vault notes, or shorter than 4 characters, do not count, and hyphenated names also match when typed with spaces, in queries and in the vault-note count alike. Private and dunder symbol names count. The names are rebuilt from the index after every sync (0.4 s for 19k chunks). On a 24-case vault golden set with one repo indexed, 0.5 raised recall@10 from 0.833 to 0.896, left a 26-case set unchanged, and kept recall@10 at 1.0 on 10 repo questions (MRR 0.864 to 0.789). `search`, `query` and `eval` accept `--code-source-weight` to override it per run.
- Embed chunks that exceed the embedding model's context length instead of failing their note. Chunks are sized in words and the model's limit is in tokens, so code-dense markdown (500 words of fenced Python is about 6,000 characters, past nomic-embed-text's 2,048 tokens) made Ollama reject the batch with HTTP 400, and the whole note was left out of the index; indexing one code repo's docs hit this on 41 spec and plan files. Such a batch is now resent once with `truncate: true` and a warning is logged. Only over-length chunks are cut (their vector covers their start); the other chunks in the batch get the same vectors as before, and keyword search still indexes every chunk's full text. Other embedding errors still fail without a retry. Run `second-brain sync` to index notes that failed before.

- Add typed graph edges (G6). Every edge now has a `type`: `links` (the existing blended vault-note edges, unchanged; stored edges are migrated to it automatically), `mentions_code` (a vault note or repo doc names a code-source file, symbol or repo through inline code, a path in prose, or a GitHub URL), and `imports` (one source file imports another in the same repo: Python modules, relative TypeScript specifiers, Go packages). Mentions link only to an unambiguous target: an exact or unique-suffix path, a symbol defined in exactly one file, or a repo's root README; bare lowercase words never match symbols, and repo docs only reach their own repo. Typed edges score `graph_weight_link × 0.7` (1.0 when mutual) and are recomputed whole on every sync, so renaming a symbol re-targets mentions in unchanged notes. `rag.related` neighbors gain `type` and, for typed edges, `evidence.code_refs`; it accepts `edge_types` to filter. `rag.connections` reports the type of its direct edge and every path hop. `rag.map` and the vault's `links` edges are unaffected. The `edges` table gains `type` and `refs_json` columns and `note_meta` gains `code_json`, added automatically; run `second-brain sync --mode full` once to record mentions for already-indexed notes.
- Add symbol chunks for code sources. A `[[code_sources]]` entry with `languages` (`"python"`, `"go"`, `"typescript"`) also indexes matching source files (`code_globs`, default all), split with tree-sitter into one chunk per function, method, class, type or interface, plus a Python module docstring. Chunk text is the symbol's leading comment, signature and docstring as written, not its body; undocumented symbols fall back to their first 12 body lines. Chunks have `kind = "code"`, `heading_path` = dotted symbol path, and `repo`, `language`, `file`, `symbol`, `symbol_name`, `parent_symbol`, `symbol_kind`, `start_line`, `end_line` and `doc` metadata. Outlines go through `redact_patterns`. tree-sitter and its grammars are an optional extra (`pip install 'second-brain-mcp[code]'`, about 4 MB); a source with `languages` fails at config load when it is missing. `eval/golden.code.toml` adds synthetic golden cases against this repo.
- Add `code_sources` to index code repositories' prose next to the vault. Each `[[code_sources]]` entry (`name`, `path`, optional `doc_globs` and `exclude_globs`) indexes the repo's markdown README, CHANGELOG, CONTRIBUTING, ARCHITECTURE, `docs/`, ADR and `decisions/` files with the markdown loader, stored under `repo:<name>/<path in repo>` with `kind = "repo_doc"` and a `repo` metadata key; `rag.search` / `rag.query` accept `filters.repo`. Listing honors the repo's `.gitignore` through `git ls-files` and always skips hidden paths, dependency and build folders (`node_modules`, `vendor`, `dist`, `build`, `target`, `venv`, …), symlinks leaving the repo, and files over 1 MB. Code-source files stay out of the vault's semantic, link, tag and co-mention graph and out of `rag.map`, so the vault graph is unchanged. Removing a source deletes its files on the next sync; a source whose path is missing, whose `git ls-files` fails inside a git repo, or whose folders or files cannot be read, is reported in sync `errors` and keeps its entries (it never falls back to a listing that skips `.gitignore`). The default is no code sources, so existing configs index exactly what they did before.
- Add a loader registry and index Obsidian `.canvas` files. The indexer now picks a parser by file extension instead of assuming markdown, and a new `include_extensions` setting (default `[".md"]`) chooses which file types are indexed, so existing vaults index exactly what they did before. With `".canvas"` included, each canvas text card becomes a chunk headed by its group labels, each file card is a link from the canvas to that exact vault path, and an arrow between two file cards is scored as a link between those two notes in the graph. Every chunk now records its source `kind` (`markdown` or `canvas`), and `rag.search` / `rag.query` accept `filters.kind` as a string or a list. Chunks indexed before this change count as `markdown`, so no re-sync is needed. Extensions without a loader, or an empty list, fail at config load. Wikilinks with a leading `/` (`[[/Folder/Note]]`) now resolve only to that exact vault path, as in Obsidian, instead of by suffix and proximity. `sync --mode file` on a file whose extension is not included now treats it like an excluded path (it is removed if it was indexed) instead of parsing it as markdown. The graph's `note_meta` table gains a `link_pairs_json` column, added automatically. PDF and HTML loaders are planned as further registry entries.
- Add an opt-in `graph_boost` (0 to 1, default 0) to `rag.search`, `rag.query`, and the CLI `search`, `query`, and `eval` commands (`--graph-boost`). After RRF fusion, retrieved chunks from graph neighbors of the five top notes gain at most one rank-1 RRF term, scaled by edge composite. Seeds do not lift each other. On a 24-case golden set, 0.25 raised recall@5 from 0.854 to 0.917 and 0.5 raised recall@10 from 0.917 to 0.938, with MRR unchanged or slightly up. 1.0 cost MRR. It stays off by default until a larger golden set confirms the gain.
- Score the graph's semantic signal with mean-centered centroid cosine (`graph_semantic_center`, default on). Raw centroid cosines bunch together (all pairs above 0.5, median 0.71 in a 648-note vault), so `graph_semantic_min` and `graph_min_edge_score` never pruned anything and every note got exactly `graph_knn_k` semantic neighbors. Centering spreads the median pair to about −0.02. The vault-mean vector is stored in a new `graph_state` table and reused by incremental syncs. Any sync that changes the scoring frame rescores every edge: the first centered build, crossing the 10-note minimum, or a new embedding dimension. Vaults with fewer than 10 embedded notes keep raw cosine. Semantic scores in `rag.related` are now on the centered scale. Run `second-brain sync --mode full` once after upgrading to rescore existing edges.
- Resolve graph wikilinks the way Obsidian does: path-qualified `[[Folder/Note]]` and relative `[[../Folder/Note]]` links, `aliases` frontmatter as a fallback when no file name matches, and `#Heading` / `#^block` / `^block` suffixes. A name shared by several notes now resolves to one note (same folder, then shallowest path) instead of linking to all of them. `rag.map` gains `ghosts`: unresolved link targets ranked by how many notes link to them. Run `second-brain sync --mode full` once after upgrading to record aliases for existing notes.
- Embed through Ollama's batch `/api/embed` endpoint instead of one `/api/embeddings` request per chunk. `embed_batch_size` (default 32) sets how many chunks go in one request; vectors keep their input order. `/api/embed` returns unit-length vectors with the same direction as before (cosine 1.0 on every chunk of a 10k-chunk test vault), and search and graph edges use cosine, so existing indexes stay valid. Note centroids now weight chunks equally (cosine ≥ 0.9995 to the old ones); a full sync is optional. A failed batch is not retried: the error names the batch and Ollama's message, and the note is reported in sync `errors`, keeps its previous index entries, and is retried on the next sync.
- Pack chunks from several notes into one `/api/embed` request during full and incremental syncs, instead of one request per note. On a 650-note vault this halves the request count but saves only a few seconds, because embedding throughput is flat from about 4 chunks per request; it matters most for vaults of many short notes. If a request holding several notes fails, each note is embedded once more on its own, so only the notes Ollama rejects are reported in sync `errors`; they keep their previous index entries and are retried on the next sync.
- Apply `redact_patterns`. The setting was loaded but never used, so configured patterns were indexed verbatim. Matches are now replaced with `[REDACTED]` in the note body, title and frontmatter values before chunking, embedding, FTS and Qdrant writes, and graph metadata; headings, tasks, tags and wikilinks are re-extracted from the redacted text. Overlapping matches from different patterns are merged into one token. File paths are not redacted. Invalid patterns or a non-list value now fail at config load. If you configured patterns, run `second-brain sync --mode full` to purge previously indexed matches; do the same after any later pattern change.
- Add `skip_headings` to leave matching sections (such as daily-journal `🔗 Related Notes` blocks) out of the index, and `embed_context_header` (default on) to prefix each embedded chunk with its note title and heading. Run `second-brain sync --mode full` once after upgrading to re-embed existing notes.
- Keyword search now ORs query terms after dropping stopwords, so natural-language questions reach the FTS leg, and indexes note titles and headings with title/heading BM25 weights. The FTS table is rebuilt automatically on the next start from existing rows; no re-sync is needed.
- Ignore markdown syntax inside code fences and inline code when parsing headings, tags, links and tasks (including fences in lists, blockquotes and callouts, which end with their container even if never closed), and keep newlines and indentation in chunk text. Run `second-brain sync --mode full` once after upgrading to re-chunk unchanged notes.
- Add `second-brain eval --golden PATH` to score retrieval with note-level recall@5, recall@10 and MRR over a TOML golden query set (`eval/golden.example.toml`). Expected paths that are not indexed notes are reported as `unknown_expected`.
- Remove `answer_draft` from `rag.query`; callers receive retrieved chunks and citations without a truncated extractive concatenation.
