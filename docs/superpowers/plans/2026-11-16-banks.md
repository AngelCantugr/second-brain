# Second-brain Banks Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task by task. Steps use checkboxes for tracking.

**Goal.** Register multiple vaults and repositories as banks and give agents one way to discover, search, fetch, sync, and explore them.

**Architecture.** Resolve all configured roots through a bank registry. Carry a structured file reference through the public API and translate it to a collision-free key at storage boundaries. Reuse the shared retrieval and graph stores and build a fresh set of stores at cutover.

**Tech stack.** Python 3.11+, TOML, SQLite FTS5, local Qdrant, Ollama, MCP Python SDK, pytest.

**Spec.** [Banks as the unit of knowledge in second-brain](../specs/2026-11-16-banks-design.md).

## Global constraints

- A single second-brain instance can index several knowledge bases and repositories. A configuration may consist entirely of vault banks or entirely of repo banks.
- Every file has a canonical bank ID and normalized, case-preserving, root-relative path. Public references use forward slashes.
- Search spans all banks by default. An explicitly empty selector or unknown bank ID is an input error.
- Ordinary wikilinks resolve within their originating bank. Automatic semantic relationships can connect eligible documents across banks.
- Fetch returns stored chunks for the selected file in source order with provenance.
- A temporarily unavailable root preserves its indexed data during full and incremental sync. Cutover uses fresh stores prepared alongside the current ones.
- Implement and test on an isolated branch from the approved design. Ship the config, tools, and bundled consumer changes together at cutover.

## Review focus

- Duplicate filenames and titles across roots never share chunks, checkpoints, or graph endpoints (Tasks 2 and 4).
- A root-relative path that escapes through a symlink cannot enter file sync (Task 2).
- A root that disappears or fails listing after a successful sync keeps its chunks and graph metadata (Task 2).
- A higher-scoring hit outside the requested bank cannot consume a result slot in either retrieval channel (Task 3).
- A bank-scoped graph query keeps the shared graph's edge scores and cannot traverse an excluded intermediate node (Task 4).

## File and interface map

| Area | Owning files | Responsibility |
| --- | --- | --- |
| Identity and registration | `second_brain/banks.py`, `config.py`, `models.py` | Validate banks and paths, encode file identity, shape provenance |
| Ingestion and maintenance | `sources.py`, `scanner.py`, `loaders.py`, `code.py`, `chunker.py`, `indexer.py`, `sync_state.py`, `watcher.py` | Select files by bank, preserve per-file state, keep scanning and watch behavior aligned |
| Retrieval | `service.py`, `keyword_store.py`, `vector_store.py`, `routing.py`, `retrieval.py`, `doc_roles.py` | Select banks before candidate truncation, return provenance and stored chunks |
| Graph | `graph.py`, `code_graph.py`, `drift.py`, graph methods in `service.py` | Resolve bank-local references, score across banks, project results by bank |
| Public and rollout | `mcp_server.py`, `cli.py`, `evaluation.py`, `eval/`, `rag_config.example.toml`, `README.md`, `second_brain/skills/second-brain/` | Expose the contract, migrate consumers, document and verify the rebuild |

Paths in the table after the first entry are relative to `second_brain/` except for `eval/`, `rag_config.example.toml`, and `README.md`.

## Cutover acceptance

For a live cutover, compare bank inventory and per-bank index totals, check same-path collisions and stored fetch, check an inferred cross-bank edge and an ordinary bank-local wikilink, then switch clients to the verified server. Keep the previous config and stores available for rollback. The implementation plan validates this sequence with disposable data. Run the live rebuild when the new server and its consumers are ready.
